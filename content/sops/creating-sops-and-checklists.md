## Description

Make sure every important work process is recorded clearly enough that another person can understand, perform, check, and improve the work.

This SOP starts with a simple checklist first. A full SOP is created only after the work is repeated, important, or needs consistency across people.

## When This SOP Is Used

Use this SOP when:

- Someone completes a recurring task and needs to record how it is done
- A new person needs to learn a task
- A task has mistakes, confusion, delays, or repeated questions
- A checklist needs to become a formal SOP
- An existing SOP or checklist needs review or improvement

## Core Principle

Start simple:

1. Record the work as a checklist
2. Use the checklist while doing the work
3. Improve the checklist after actual use
4. Convert it into an SOP only when the process is stable enough

## Roles and Responsibilities

| Role | Responsibility |
|---|---|
| Work Owner | Records the task they personally do and creates the first checklist |
| Peer Reviewer | Tests whether the checklist is understandable and usable |
| Unit Lead | Decides whether the checklist should become an SOP |
| SOP Coordinator | Maintains naming, versioning, storage, and review dates |
| Approver | Confirms that the SOP is ready to be used by the team |

## Inputs Needed Before Starting

- The real task has been completed at least once
- The person who actually does the work
- Any links, files, folders, trackers, tools, or examples used in the task
- Known mistakes, blockers, or quality checks
- Clear output expected from the task

## Steps

### Step 1: Capture the Work

The Work Owner writes down what they did immediately after completing the task.

Capture:

- Task name
- When the task is done
- Why the task matters
- Step-by-step actions
- Tools, files, folders, or trackers used
- Output created
- Mistakes or problems noticed
- Proof that the work is complete

At this stage, do not try to make a perfect SOP. Just record the real work clearly.

### Step 2: Create a Simple Checklist

Convert the recorded work into a short checklist. Each checklist item should begin with an action verb.

Good examples:

- Open the lesson folder
- Check that the required subfolders exist
- Add missing files to the correct folder
- Update the tracker with the folder link
- Ask the Unit Lead if access is missing

Avoid vague checklist items:

- Manage folder
- Do design properly
- Finish everything

### Step 3: Use the Checklist Once

The Work Owner uses the checklist while doing the task again. During use, mark:

- Steps that were missing
- Steps that were confusing
- Steps that were in the wrong order
- Decisions that needed senior input
- Quality checks that should be added

### Step 4: Peer Test the Checklist

Give the checklist to another person and ask them to follow it.

The peer should answer:

- Can I understand when to use this?
- Can I complete the work without asking many questions?
- Do I know what files, tools, or trackers to use?
- Do I know what "done" looks like?
- Do I know what to do if something is missing?

### Step 5: Decide Whether It Needs a Full SOP

Create a full SOP if the task is:

- Repeated often
- Done by more than one person
- Important for quality or safety
- Easy to misunderstand
- Connected to handover between people
- Needed for onboarding

Keep it as a checklist if the task is:

- Simple
- Personal
- Temporary
- Used by only one person
- Still changing heavily

### Step 6: Draft the Full SOP

Use this structure:

1. SOP header
2. Purpose
3. When this SOP is used
4. Roles and responsibilities
5. Inputs
6. Step-by-step process
7. Checklist / quality gate
8. Outputs / definition of done
9. Common mistakes / red flags
10. Related tools, templates, and links
11. Review history

Write the SOP for the person who will do the work, not for the person who already knows the work.

### Step 7: Review and Approve

Before approval, check:

- The SOP has an owner
- The trigger is clear
- Inputs are clear
- Steps are in the correct order
- Each step starts with an action
- The quality checklist is practical
- Outputs are specific
- Common mistakes are included
- Related links are included
- Version and review date are updated

### Step 8: Publish and Train

After approval:

1. Save the SOP in the correct folder
2. Add it to the SOP index or tracker
3. Inform the people who will use it
4. Use it in actual work
5. Collect questions and improvements

### Step 9: Improve Through Use

Review the SOP when:

- A mistake repeats
- A tool, file, folder, or tracker changes
- A new person struggles to follow it
- The process changes
- The scheduled review date arrives

## Quality Gate

An SOP or checklist is ready only if a new or less experienced person can use it to complete the work with minimal explanation.

## Outputs

The process should produce one or more of these:

- Simple work checklist
- Full SOP
- Updated SOP index
- Updated tracker or work log
- Review notes
- Version history

## Naming Standard

Use clear names:

**Checklist:** `Checklist - [Task Name] - v[Number]`

**SOP:** `SOP - [Process Name] - v[Number]`

Examples:

- `Checklist - Lesson Folder Setup - v1.0`
- `SOP - Lesson Design - v1.0`
- `SOP - Book Compilation - v1.0`

## Version Standard

| Version | Use |
|---|---|
| v0.1 | First rough draft |
| v0.2 | Improved after first use |
| v0.5 | Peer-tested draft |
| v1.0 | Approved for team use |
| v1.1 | Minor update |
| v2.0 | Major process change |

## Common Mistakes

- Writing an SOP before understanding the real work
- Making the SOP too long for a simple task
- Writing rules but not adding a checklist
- Forgetting to define the output
- Not assigning an owner
- Using names of people instead of roles
- Keeping outdated links or tool instructions
- Not recording improvements after use
