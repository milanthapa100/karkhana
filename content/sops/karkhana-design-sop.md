# Karkhana Design SOP

> **Standard Operating Procedure for Lesson Design, Book Design & Print Production**

This SOP provides a common design system and workflow for creating Karkhana educational materials.

It is designed to help both **new and experienced designers** understand how to move from approved lesson content to a consistent, review-ready, and print-ready Karkhana book.

---

## 1. Purpose

The purpose of this SOP is to ensure that all Karkhana educational materials are:

* Consistent across grades and lessons
* Easy for learners to understand
* Visually engaging without being distracting
* Technically correct for printing
* Easy for designers to edit and maintain
* Consistent with the Karkhana visual identity
* Properly reviewed before final production

The SOP covers the complete process from **design setup to final print handoff**.

---

## 2. Scope

This SOP applies to:

* Lesson design
* Worksheet design
* Activity sheets
* Grade books
* Lesson covers
* Educational illustrations
* Diagrams
* Tables and worksheets
* ICT/activity pages
* Curriculum mapping pages
* Print-ready PDFs
* Book assembly and final production

# 3. Design Philosophy

Karkhana design should support **learning first**.

A good design should answer three questions:

1. **Can the learner understand it?**
2. **Can the learner find the important information quickly?**
3. **Does the design make the learning experience interesting?**

> **Design is not decoration. Design is a tool that helps learners understand, explore, and remember.**

### Karkhana Design Principles

| Principle            | What it means                                                                |
| -------------------- | ---------------------------------------------------------------------------- |
| **Learning First**   | Content and learning objectives always come before decoration.               |
| **Clarity**          | Learners should immediately understand what to read or do.                   |
| **Consistency**      | Similar components should look and behave similarly.                         |
| **Age Appropriate**  | Typography, visuals, instructions, and layouts should match the grade level. |
| **Visual Hierarchy** | Important information should be visually easy to identify.                   |
| **White Space**      | Do not fill every empty space with graphics.                                 |
| **Practicality**     | Activities should be easy to follow and use.                                 |
| **Print Ready**      | Final files must meet technical printing requirements.                       |

## 5.1 Designer

The designer is responsible for:

* Setting up the design file
* Following the Karkhana design system
* Creating lesson layouts
* Placing illustrations and assets
* Maintaining typography and spacing
* Applying colors correctly
* Managing design versions
* Resolving design feedback
* Performing design QA
* Preparing print-ready files

---

## 5.2 Lesson / Content Owner

The content owner is responsible for:

* Providing approved content
* Checking factual accuracy
* Checking instructions
* Checking activity sequence
* Checking curriculum alignment
* Approving final content

The design lead is responsible for:

* Maintaining design consistency
* Reviewing major design decisions
* Approving templates and systems
* Checking book-level consistency

* Paper specifications

## 8.1 Print Setup

For standard print production:

| Setting                 | Standard                                |
| ----------------------- | --------------------------------------- |
| Color                   | CMYK                                    |
| Raster image resolution | 300 ppi where appropriate               |
| Bleed                   | 3 mm unless printer specifies otherwise |
| Crop marks              | According to printer requirement        |
| Output                  | Print-ready PDF                         |
| Page count              | Confirm with binding/printing method    |

> **Important:** Page count requirements depend on the binding method. For saddle-stitch or signature-based printing, pages are commonly produced in multiples of 4, but always confirm with the printer.

* What is the learner expected to do?

* Which content needs an illustration?

# 13. Curiosity Design

Curiosity should visually invite the learner to explore.

### Curiosity should have:

* Clear heading
* Short and readable text
* Strong visual hierarchy
* Relevant illustration
* Enough white space
* Clear question or challenge

### Avoid:

* Too much text
* Unnecessary decoration
* Too many colors
* Overcrowded illustrations
* Tiny text

---

# 14. Activity Design

Activity pages should make it immediately clear:

1. What should I do?
2. What materials do I need?
3. What steps should I follow?
4. What should I record?
5. What should I discuss?

### Activity Structure

```text
ACTIVITY NUMBER
      ↓
ACTIVITY NAME
      ↓
TIME / MATERIALS
      ↓
WHAT TO DO
      ↓
STEPS
      ↓
OBSERVE / RECORD
      ↓
DISCUSS / THINK
```

---

# 15. Activity Design Rules

### Do

* Use numbered steps.
* Keep instructions short.
* Use action words.
* Give enough writing space.
* Use diagrams when they improve understanding.
* Keep the material list easy to scan.

### Don't

* Put long paragraphs inside activity instructions.
* Use unnecessary decorative elements.
* Put multiple instructions into one dense paragraph.
* Make writing areas too small.
* Use confusing numbering.

# 25. Layout Rules

## 25.1 White Space

White space is part of the design.

Avoid:

```text
CONTENT + CONTENT + IMAGE + TEXT + ICON + TEXT + IMAGE
```

Prefer:

```text
CONTENT

      VISUAL

CONTENT

      QUESTION
```

Give learners visual breathing space.

---

## 25.2 Alignment

Use consistent alignment.

Preferred:

* Shared left edges
* Consistent margins
* Consistent spacing
* Consistent baseline alignment
* Consistent image alignment

Avoid randomly placing objects simply because there is empty space.

* Keep column headings clear.
* Avoid unnecessary borders.
* Maintain adequate row height.
* Do not make text too small.
* Ensure tables do not split confusingly across pages.

# 29. File Naming Convention

Use a consistent naming system.

### Lesson InDesign File

```text
KL0226_Measure_Mania_INDD_2083_v01.indd
```

### Lesson PDF

```text
KL0226_Measure_Mania_PDF_2083_v01.pdf
```

### Recommended Structure

```text
[LessonCode]_[LessonName]_[FileType]_[Year]_[Version]
```

### Examples

```text
KL0225_Time_INDD_2083_v01.indd

KL0225_Time_PDF_2083_v01.pdf

KL0226_Measure_Mania_INDD_2083_v02.indd
```

> Avoid file names such as `final_final2.indd`, `newfinal.indd`, or `latest.pdf`.

# 30. Version Control

Use clear versions.

```text
v01 → First design
v02 → First revision
v03 → Second revision
v04 → Final approved version
```

For example:

```text
KL0225_Time_INDD_2083_v01.indd
KL0225_Time_INDD_2083_v02.indd
KL0225_Time_INDD_2083_v03.indd
```

Once a file is approved, do not overwrite the approved version without maintaining version history.

# 43. Common Design Problems

| Problem                    | Solution                                                            |
| -------------------------- | ------------------------------------------------------------------- |
| Page feels crowded         | Remove unnecessary decoration and increase spacing.                 |
| Too many fonts             | Return to approved typography system.                               |
| Text is too small          | Increase size and restructure content.                              |
| Activity is confusing      | Break instructions into numbered steps.                             |
| Illustration does not help | Replace it with a learning-supporting visual.                       |
| Pages look inconsistent    | Check the design system and component styles.                       |
| Too much empty space       | First ask whether the space improves readability before filling it. |
| Images look blurry         | Replace with higher-resolution assets.                              |
| Text is cut off            | Check margins, bleed, and text frames.                              |
| PDF has missing images     | Check links before export.                                          |
| Font changes after opening | Check installed fonts and document font usage.                      |

# 44. Do & Don't

| Do                             | Don't                                |
| ------------------------------ | ------------------------------------ |
| Use consistent spacing         | Randomly change spacing              |
| Use approved fonts             | Add unnecessary fonts                |
| Use relevant visuals           | Decorate every empty space           |
| Keep instructions clear        | Use long confusing paragraphs        |
| Give learners writing space    | Fill the page completely             |
| Maintain character consistency | Change character appearance randomly |
| Check the full book            | Review only individual pages         |
| Maintain versions              | Use `final_final2` filenames         |
| Check licensing                | Assume online images are free        |
| Pre-flight before export       | Export without checking              |

# 47. When You Are Stuck

Before asking for help, check:

1. What is the learning objective?
2. What does the learner need to do?
3. What information is most important?
4. Can the layout be simplified?
5. Is the problem content or design?
6. Have you followed the existing template?
7. Have you checked similar approved lessons?

If the issue is still unclear:

> **Ask the Design Lead / Curator before making a major design-system change.**

---

# 48. Final Design Principle

> **A good Karkhana design makes learning easier, not just the page prettier.**

Every design decision should support at least one of these:

```text
UNDERSTAND
   ↓
EXPLORE
   ↓
DO
   ↓
DISCUSS
   ↓
REFLECT
   ↓
REMEMBER
```

If a visual element does not support the learner, the content, or the learning experience, reconsider whether it is necessary.
